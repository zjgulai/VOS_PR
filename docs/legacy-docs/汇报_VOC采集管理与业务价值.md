# 汇报材料：VOC 采集管理与业务价值

> 面向业务方：可用于 PPT 分章或 Word 目录；**详细业务结论**仍以 `C_结果与交付/07_综合交付` 内综合总报告、升级计划为准，本文作 **摘要与叙事线**。

## 1. 背景与目标

- **背景**：母婴出海需基于本地化 **VOC（用户声音）** 做市场优先级、品线、渠道与价格策略决策。
- **目标**：建立可复用的 **采集—证据—汇总—决策引用** 闭环，并沉淀为综合工作簿与总报告，支撑 **15 国** 等级别的升级并入与业务评审。

## 2. 采集与证据体系

### 2.1 来源分级（L1–L5 等）

- 在研究框架中区分 **官方 / 专业机构 / 垂直媒体 / 电商与社区 / 长尾**，用于证据强度与回填优先级（详见总报告与各国正式包中的证据码说明）。

### 2.2 证据码与可追溯

- 正式完整版并入综合工作簿时，使用 **证据码** 与明细表对照，保证 **可复核、可迭代**。

### 2.3 外部数据需求与迭代

- **需求索引**：`A_方案与标准/00_输入资料与调研/03_外部数据需求清单.md`  
- 与综合工作簿新增 sheet、数仓字段 **对齐**，按波次（Wave2/Wave3）与 TOP20 二次升级 **迭代**。

### 2.4 Wave 试点

- **Wave2 轻深挖**、**Wave3 模板验证**：降低扩国家试错成本，路径见 `B_过程与资产/09_升级国家深挖框架/` 下 `11_`、`15_` 等目录。

## 3. 数据与产物管理

### 3.1 综合工作簿与「四张升级表」心智

- 综合工作簿承载 **升级后的关键 sheet**（客群矩阵、购买力/价格敏感、信息源质量、cluster 策略卡等），与 **业务评审版** 双轨服务不同读法。

### 3.2 管理闭环

```text
试点（Wave） → 前置补证 → 底稿（完整版） → 正式完整版 → integrate 并入主簿 / 评审版
```

- 脚本入口集中在 `B_过程与资产/08_生成脚本/09_升级国家深挖框架/`。

### 3.3 目录与版本

- 物理目录 **A / B / C** 分离 **方案、过程、结果**，避免评审版与过程稿混读；路径由 `config/project_paths.py` 统一，减少硬编码漂移。

## 4. 对业务的价值（四决策）

| 决策域 | VOC 能回答什么 | 参考落地 |
|--------|----------------|----------|
| **市场** | 国家优先级、区域 cluster、扩国家顺序 | 综合总报告、TOP20、升级计划 |
| **产品** | 品线×场景、痛点与必备功能 | 各国正式包、矩阵 sheet |
| **营销** | 平台入口、内容切口、信任来源 | 平台/关键词/P1、cluster 策略卡 |
| **价格** | 购买力层级、促销敏感度、套装/赠品偏好 | 购买力地图、各国正式包价格预设 |

## 5. 后续迭代（方向）

- **TOP20 二次升级**（方法见 `TOP20二次升级试点说明.md`）
- **P2 扩源**与长尾国家模板化（`14_Wave3观察池cluster模板` 等）
- **合规与刷新**：证据 URL 与平台规则变更的例行复核
