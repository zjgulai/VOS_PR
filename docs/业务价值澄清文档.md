# 业务价值澄清文档

> 版本：v1.0 | 日期：2026-08-12  
> 性质：**价值锚点文档**——在开始开发任何功能之前，先明确它对业务产生什么具体改变  
> 原则：每一条价值主张都必须能回答"如果没有这个，PR/社媒团队现在怎么做？"

---

## 一、现状：没有这个系统，他们怎么做

**PR 团队现状（已确认的痛点）：**

| 场景 | 现在的做法 | 痛点 |
|------|-----------|------|
| 了解竞品动态 | 人工刷 Google、偶尔看 Forbes 等媒体 | 滞后 1-2 周，靠运气 |
| 监测风险信号 | KleanPal 诉讼是偶然发现的（未建立系统）| 已知风险仍有盲区 |
| 发现 pitch 机会 | 凭经验判断，无数据支撑 | 错过窗口期 |
| 了解编辑选题 | 个人关系 + 手动浏览媒体 | 覆盖面极窄 |
| 撰写周报 | 手动搜集 + 人工汇总 | 每周 3-5 小时 |

**社媒团队现状（已确认的痛点）：**

| 场景 | 现在的做法 | 痛点 |
|------|-----------|------|
| 了解用户在讨论什么 | 人工刷 Reddit/TikTok | 不系统，覆盖不全 |
| 监测竞品内容策略 | 偶尔看竞品账号 | 无法判断趋势 |
| 发现趋势 | 刷算法推送 | 被动，无法主动识别 |
| 分析 KOL 内容 | 人工看 | 费时且主观 |
| 输出内容建议 | 基于经验，无数据 | 说不清楚为什么这么做 |

## 二、PR Intelligence：产出什么，对谁有用

### 2.1 核心交付物

**每周一份 PR Intelligence Report**，固定结构，固定时间（周一生成草稿，Analyst 审核后发布）：

```
本周报告的四个问题：
1. 媒体和行业发生了什么？（Monitoring）
2. 对 Momcozy 意味着什么？（Insights）
3. 有哪些机会和风险？（Opportunities & Risks）
4. PR 接下来应该做什么？（Actions）
```

**实时预警**（不等周报）：
- P0 信号（Sev4）：15 分钟内推送
- P1 信号（Sev3）：60 分钟内推送

### 2.2 对谁有用，解决什么问题

| 受众 | 具体价值 | 没有系统时他们损失什么 |
|------|---------|---------------------|
| **Global PR Lead** | 每周 30 分钟看完周报，掌握全局，不再靠碎片信息决策 | 信息不对称，决策滞后 |
| **Regional PR** | 每天上午看 P0/P1 预警，及时响应本地风险 | 风险发现延迟 1-2 周 |
| **PR Analyst** | 有结构化数据支撑 pitch 推荐和媒体选择 | 只能靠经验，说不清楚理由 |
| **Legal/Privacy** | 监管预警自动触达，不靠人工盯 | KleanPal 诉讼就是典型的"应该更早知道" |

### 2.3 三个可量化的价值指标

**指标1：风险提前量**

```
定义：从风险首次出现到 PR 团队确认的时间
当前水平：未测量（KleanPal 诉讼发现延迟未知）
目标：P0 信号 < 4小时，P1 信号 < 24小时
测量方法：记录每条 Sev3+ 信号的首次发现时间 vs PR 确认时间
```

**指标2：pitch 成功率提升**

```
定义：基于系统建议进行的 pitch，媒体回复率 vs 历史基线
当前水平：未测量（PR 团队目前无 pitch 数据记录）
目标：建议 pitch 的回复率 > 非建议 pitch 的 1.5倍
测量方法：dim_media_contacts 表记录每次 pitch 结果
前提条件：需要先建立历史基线（3个月数据）
```

**指标3：周报生产效率**

```
定义：从数据采集完成到周报发布的人工工时
当前水平：估计 3-5 小时/周（手动模式）
目标：< 60 分钟/周（Analyst 审核 + 修改）
测量方法：周报发布时间戳 - 数据冻结时间戳
注意：这是最快可以测量的指标，第一份周报就能开始记录
```

### 2.4 不做什么（边界）

| 不做 | 原因 |
|------|------|
| AI 自动发送 pitch 邮件 | 原始需求明确："任何外部联系必须人工审批" |
| 自动发布声明或回应 | 同上 |
| 替代人工判断 | 系统提供建议，人工做决定 |
| 覆盖所有 53 个国家 | 第一阶段只做英语市场（TOP20 里美/英/加/澳 = 约 60% 销售额）|

## 三、社媒 Intelligence：产出什么，对谁有用

### 3.1 核心交付物

**每周一份 Social Media Intelligence Report**，四个模块：

```
S1 用户讨论洞察：
  → 本周用户在 Reddit/Instagram/Facebook Groups/TikTok/YouTube 上
    讨论了什么？最关注哪些问题？有什么新的痛点或需求信号？

S2 竞品社媒动态：
  → 竞品本周发了什么内容？哪些内容表现突出？
    与哪些 KOL 合作？用了什么创意形式？

S3 趋势洞察：
  → 本周哪些 Hashtag/BGM/内容模板正在升温？
    哪些与母婴相关？品牌是否适合跟进，时间窗口是什么？

S4 KOL 内容分析：
  → 重点 KOL 本周发了什么？受众反馈如何？
    是否有合作机会或潜在风险？

→ Action 建议：基于以上，本周社媒团队应该做什么？
```

### 3.2 对谁有用，解决什么问题

| 受众 | 具体价值 | 没有系统时的损失 |
|------|---------|----------------|
| **社媒内容负责人** | 有数据支撑内容选题，不再靠感觉判断热点 | 内容错过时间窗口，或追已经凉的趋势 |
| **竞品监控负责人** | 每周竞品内容全览，不再靠人工刷账号 | 竞品重要 campaign 被遗漏 |
| **KOL 合作负责人** | 知道哪些 KOL 在给竞品做内容，识别合作机会 | 错过优质 KOL，或重复接触已被竞品锁定的 KOL |
| **内容创作团队** | 知道什么内容形式在平台上跑得好，有参考素材 | 只能复制已有经验，无法快速迭代 |

### 3.3 三个可量化的价值指标

**指标1：趋势参与时效性**

```
定义：从趋势被系统识别到团队发布相关内容的时间
当前水平：未测量
目标：高热趋势识别后 72 小时内发布内容
测量方法：social_trends 表的 first_seen 时间 vs 品牌发布时间
```

**指标2：竞品内容覆盖完整度**

```
定义：系统采集到的竞品 P0 账号内容数 / 竞品实际发布内容数
当前水平：TikTok 约 70%（已验证），其他平台 0%
目标：三主要平台（TikTok/Instagram/YouTube）覆盖率 > 85%
测量方法：定期人工抽查竞品账号，对比系统数据
```

**指标3：高价值信号识别率**

```
定义：系统标记为"高优先级"的内容中，被团队判断为"有价值"的比例
当前水平：无基线
目标：Sev3+ 信号中 > 60% 被团队评价为有价值
测量方法：dim_competitor_kol_collabs.verified 字段 + 人工反馈
```

### 3.4 不做什么（边界）

| 不做 | 原因 |
|------|------|
| 自动发布内容 | 品牌内容必须人工创作和审批 |
| 替代 KOL 合作决策 | 系统提供候选，BD 团队做商务判断 |
| 分析竞品私密数据 | 只采集公开内容 |
| 覆盖所有 TOP20 市场 | 第一阶段只做英语市场 + 东南亚（有 Shopee 数据）|

## 四、两条产品线的共同约束

这是防止范围蔓延的明确边界：

| 约束 | 说明 |
|------|------|
| **输出是草稿，不是决策** | AI 生成内容，人类做决定 |
| **引用必须可追溯** | 每条洞察都指向原始来源 URL |
| **不采集私密数据** | 只采集公开内容，不绕过登录墙采集私人帖子 |
| **不做自动外联** | 不自动发邮件、不自动@媒体、不自动发布任何内容 |
| **Reddit 商业协议** | 系统化 Reddit 接入需要正式商业协议，当前用 TikHub 替代方案 |

## 五、数据基建与业务价值的对应关系

> 这一节说明"为什么要建那些表和采集器"——每个技术组件对应什么业务价值

| 技术组件 | 支撑的业务场景 | 没有它会怎样 |
|---------|--------------|------------|
| `social_posts` 表 | S1/S2 全部模块的数据基础 | 无法分析用户讨论和竞品内容 |
| `dim_competitor_kol_collabs` 表 | S2 竞品×KOL 合作情报 | 不知道竞品在和谁合作，错过拦截机会 |
| `dim_creator_profiles` 表 | S4 KOL 分析 + 合作决策 | 每次接触 KOL 前都要重新调研 |
| `pr_articles` 表 | PR-1 品牌报道监测 | 漏掉竞品 PR 稿和媒体覆盖变化 |
| `pr_risk_signals` 表 | PR-2 风险预警 | 无法定量排序风险优先级 |
| `v_content_quality_scores` 视图 | 全系统内容过滤和排序 | 噪音太多，重要信号被淹没 |
| `dim_competitor_social_accounts` | S2 竞品社媒动态 | 无法系统监控竞品官方发什么 |
| `dim_info_source_quality` 扩展 | 信息源权重计算 | 所有来源同等对待，低质数据干扰决策 |
| `monitor.py` 监管 RSS | PR-2 监管风险预警（P0）| 下一个 KleanPal 诉讼仍然是"偶然发现" |
| `feed_collector.py` 媒体 RSS | PR-1 媒体监测 | 只靠人工搜索，覆盖不到 5% 的相关报道 |

## 六、最小可验证价值（第一个月能证明什么）

**第一个月结束时，用以下具体证据验证系统有没有价值：**

**PR Intelligence 验证点：**

1. ✅ 系统至少发现 1 条 Sev3+ 风险信号，PR 团队确认"这是有价值的"
2. ✅ 周报草稿审核时间 < 60 分钟（vs 手工 3-5 小时）
3. ✅ 至少识别出 1 个媒体 pitch 机会（有明确的媒体 + 角度 + 时间窗口）

**社媒 Intelligence 验证点：**

1. ✅ 发现 1 个此前未知的竞品 KOL 合作（从 dim_competitor_kol_collabs）
2. ✅ 识别出 1 个趋势，社媒团队判断"这个我们本来会错过"
3. ✅ TikTok/Instagram/YouTube 三平台竞品内容覆盖率 > 70%

**如果第一个月这 6 点都达不到，说明：**
- 要么采集器没有正常运行（技术问题）
- 要么信息源选择错了（策略问题）
- 要么关键词配置不准（配置问题）

三种情况的修复方向完全不同，所以必须在第一个月内验证。

## 七、尚未澄清的问题（需要业务确认）

这些问题当前无法从需求文档中得到答案，需要与 PR/社媒团队确认：

| 问题 | 影响 | 优先级 |
|------|------|--------|
| PR 团队有多少人？PR Intelligence 报告发给谁？| 决定报告详细程度和审核流程 | P0 |
| 社媒团队有多少人负责竞品监控？| 决定 S2 的自动化程度 | P0 |
| 现在是否有任何监测工具在用（Meltwater/Brand24等）？| 避免重复建设，找到集成点 | P1 |
| 周报是中文还是英文？| 影响 LLM prompt 和输出质量 | P1 |
| KOL 合作决策由谁做？BD 还是社媒团队？| 决定 dim_creator_profiles 的字段优先级 | P1 |
| 是否有预算购买 Muck Rack / Modash 等工具？| 影响媒体接触数据和 KOL 数据的获取方式 | P2 |
