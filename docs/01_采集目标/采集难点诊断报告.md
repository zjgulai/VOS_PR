# 采集难点诊断报告

## 1. 问题分类

当前采集难点可归纳为三类：

1. 登录墙与权限限制（账号态）
2. 反爬与动态渲染（技术门槛）
3. 评论树与深链补抓（结构复杂）

## 2. 平台问题映射（按执行优先级）

| 场景 | 典型平台 | 现象 | 推荐策略 | 可用 Skill |
|---|---|---|---|---|
| 评论树缺失 | Amazon 多国家站点 | 评论只展示摘要，明细需深链 | ASIN API + 深链分页回补 | `asin-data-api-automation` |
| 登录墙 | Shopee / Lazada | 商品评论需登录，匿名态受限 | 登录墙队列 + 手工 SOP + 代理补抓 | `brightdata-automation` |
| 深链登录 | TikTok / Facebook | 评论层级需账号态才能完整展开 | 公开帖优先 + 登录态补录 + 链路留痕 | `facebook-automation` |
| 反爬拦截 | MercadoLibre 等电商平台 | 高频请求触发风控、返回壳页 | 代理 + 限速 + 重试策略 | `brightdata-automation` |
| JS 渲染与分页 | 论坛/社区平台 | 初始页面无完整正文与评论 | 浏览器态抓取 + DOM 分段抽取 | `firecrawl-automation` |
| 特殊反爬页面 | 微信公众号等 | 直接请求容易失败 | 代理转译抓取 + Playwright 补抓 | `markdown-proxy` |

## 3. 现状风险

- 执行脚本数量大、管理分散
- 失败类型未标准化，复盘成本高
- 半自动流程依赖个人经验，难以复制

## 4. 登录墙处理标准

### 4.1 状态机

- `login_wall_detected`：识别到登录限制
- `manual_required`：进入人工处理队列
- `manual_in_progress`：人工处理中
- `manual_done`：处理完成并回填
- `manual_blocked`：无法处理（需升级策略）

### 4.2 最小留痕字段

- 任务 ID
- 国家 / 平台
- URL
- 失败页面摘要
- 处理方式
- 处理结果
- 处理人
- 时间戳

## 5. 改造目标

- 建立统一任务状态模型（含登录墙专用状态）
- 建立平台级 SOP（自动/半自动/人工）
- 建立可追踪回补链路（失败 -> 指派 -> 回补 -> 复核）

## 6. 结果定义

当以下条件满足时，认为采集流程进入可产品化：

- 每个任务都有状态与日志
- 登录墙问题有标准处理记录
- 失败任务可自动重试或明确指派
- 采集输出可直接进入 dwd 层分析
