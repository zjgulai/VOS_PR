# 周会闭环操作手册（运营版）

适用对象：运营同学、项目 PM、值班分析师  
目标：每周固定时间完成“登录墙回补 -> 任务回推/重试 -> 导出周会包 -> 留痕审计”

## 0. 准备条件

- 前后端已启动：
  - 前端：`http://127.0.0.1:3000`
  - 后端：`http://127.0.0.1:8000`
- 已有本周任务执行记录（任务队列里可看到 `success/failed/login_wall`）
- 有至少 1 位负责人处理登录墙记录（`owner` 字段不为空更佳）

## 1. 先做登录墙处理（5-10 分钟）

路径：`/admin/voc-collection` -> 登录墙面板

1. 按 `status` 过滤 `manual_required` / `manual_in_progress`
2. 勾选本周已处理完的记录，批量更新为 `manual_done`
3. 补齐 `owner` 与 `note`（建议备注“处理方式+结果”）
4. 仍无法处理的记录标记 `manual_blocked`，备注阻塞原因

完成标准：
- `manual_done` 有新增
- 关键国家/平台无“无人认领”记录

## 2. 执行周会闭环（3-5 分钟）

路径：`/admin/voc-collection` -> 批次管理面板

建议参数（默认）：
- 闭环窗口：`7` 天
- 最大记录：`200`
- 回推后执行：勾选
- Dry Run：先勾选（第一轮）

操作顺序：
1. 点击“执行周会闭环”（Dry Run）
2. 检查结果提示：来源记录、选中记录、回推任务、执行数
3. 取消 Dry Run 再执行一次真实闭环

完成标准：
- 出现 `closure_run_id`
- `weekly_closure_history` 有新增记录

## 3. 闭环历史筛选与复盘（3 分钟）

路径：同页“闭环历史”

1. 设定筛选：
   - 历史天数（建议 7 或 14）
   - 运行模式（`run_now` / `requeue`）
   - 执行模式（`dry` / `real`）
2. 查看本周记录是否完整
3. 点击“导出闭环历史 CSV”留档

## 4. 一键重试失败任务（2-5 分钟）

路径：闭环历史表格“重试失败任务”

建议：
- 先勾选“重试 Dry Run”
- 对异常 run 点击“重试失败任务”
- 确认重试任务数量后，再做真实重试

适用场景：
- 网络抖动、临时 403、偶发超时
- 不适用长期登录墙（应先回到步骤 1 处理）

## 5. 导出周会材料（2 分钟）

建议导出两份：

1. 周会闭环包（XLSX）  
   接口：`/api/v1/collection/weekly-closure-export-xlsx?days=7`  
   用途：周会主材料（含 overview、batch、trend、owner、login_wall）

2. 闭环历史（CSV）  
   接口：`/api/v1/collection/weekly-closure-history-export?...`  
   用途：审计留痕与复盘附件

## 6. 周会口径模板（可直接复述）

- 本周闭环范围：近 `X` 天，共 `N` 条人工记录进入闭环
- 回推任务：`A` 个，执行 `B` 个，成功 `C` 个，失败 `D` 个
- 登录墙处理：`manual_done` 新增 `E` 条，`manual_blocked` `F` 条
- 主要风险：平台/国家/原因（1-3 条）
- 下周动作：负责人 + 截止时间

## 7. 常见问题

- 看不到闭环历史新增？
  - 先确认是否产生了 `closure_run_id`
  - 再检查筛选条件是否过严（days/run_mode/exec_mode）

- 重试后数量为 0？
  - 该次 run 的 `payload.results` 里可能没有失败项
  - 或任务已被人工改为 `success/skipped`

- owner 汇总为空？
  - 本周登录墙记录可能都没有 owner
  - 先在登录墙面板批量补 owner 再刷新
