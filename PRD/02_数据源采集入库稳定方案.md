# 数据源采集入库稳定方案

> 版本：v1.0 | 日期：2026-08-13
> 依据：2026-08-13 用真实 API Key 逐平台实测（TikHub + Apify）

## 二、平台分治策略（核心决策）

**不要用 TikHub 覆盖所有平台**——它的强项是 TikTok/Douyin（主战场）与 Reddit/Instagram，YouTube 端点在当前 Key 等级下不可用。

```
第一梯队分治：
  TikTok     → TikHub（✅ 已稳定）
  Reddit     → TikHub（✅ 已稳定）
  Instagram  → TikHub（✅ 需改代码，用 v3→v1 流程）
  YouTube    → Apify streamers/youtube-scraper 或官方 YouTube Data API v3（免费配额）
  Facebook Pages  → Apify（actor 待核实）
  Facebook Groups → Apify facebook-groups-scraper（ToS 确认后）

第二梯队兜底（GitHub data-achieve 列表）：
  Agent-Reach（71k⭐，零 API 费）：Reddit / YouTube / Twitter 兜底
  browser-use / browser-harness：Facebook Groups / Instagram 登录态浏览器自动化
  firecrawl（166k⭐）：通用网页抓取
  TikHub-API-Python-SDK：官方 SDK，替换手写 httpx 端点
```

**每平台必须满足双源可切换**：主源失败自动降级到兜底，不出现单点（对应批次 1 的「覆盖率诚实表达」铁律）。

## 三、正确调用方式（官方 SDK，替代手写端点）

现有 6 个采集器全是手写 `httpx` 端点，其中 Instagram/YouTube 端点已确认错误。改用官方 `tikhub` SDK（已安装 v2.1.2，1010 端点 100% 覆盖，自带重试/限流处理）。

### 3.1 统一初始化

```python
from tikhub import TikHub
client = TikHub(api_key=os.environ["TIKHUB_API_KEY"])  # 自动读 TIKHUB_API_KEY
```

### 3.2 各平台正确方法（本次实测确认，全部通过）

```python
# TikTok 竞品账号内容
r = client.tiktok_web.fetch_user_post_videos(unique_id="willowpump", count=20)

# Reddit 关键词/社区搜索
r = client.reddit_app.fetch_dynamic_search(query="momcozy breast pump review")

# Instagram：两步流程（旧代码漏了第一步）
uid = client.instagram_v3.get_user_id_by_username(username="elvie")  # 先拿数字 user_id
posts = client.instagram_v1.fetch_user_posts(user_id=uid, count=20)  # 再拉帖子
# Hashtag 监听
ht = client.instagram_v1.fetch_hashtag_posts(hashtag="breastpump")

# YouTube（Apify streamers~youtube-scraper，实测返回 3 条真实数据）
youtube = httpx.post(
    "https://api.apify.com/v2/acts/streamers~youtube-scraper/run-sync-get-dataset-items",
    params={"token": os.environ["APIFY_API_KEY"]},
    json={"searchQueries": ["momcozy breast pump"], "maxResults": 20},
)

# Facebook Pages（Apify facebook-posts-scraper，实测返回 5 帖）
fb = httpx.post(
    "https://api.apify.com/v2/acts/apify~facebook-posts-scraper/run-sync-get-dataset-items",
    params={"token": os.environ["APIFY_API_KEY"]},
    json={"startUrls": [{"url": "https://www.facebook.com/babybrezza/"}],
          "resultsLimit": 20, "onlyPostsNewerThan": "30 days"},
)
```

**关键差异记录**（旧代码 vs 正确）：

| 采集器 | 旧代码（错误） | 正确 |
|---|---|---|
| YouTube 搜索 | `search_video(keyword=...)` | `search_video(search_query=...)`；且当前 Key 返回恒 0，需切源 |
| YouTube 频道 | `get_channel_videos_v2(channel_id=@handle)` | 端点返回 400，需切源 |
| Instagram 账号 | `web/get_user_info_and_media_v2?username=` | `v3.get_user_id_by_username` → `v1.fetch_user_posts(user_id)` |
| Facebook Pages | `startUrls: ["https://..."]`（字符串数组）+ `maxPostsPerProfile` | `startUrls: [{"url": "https://..."}]`（对象数组）+ `resultsLimit` |

## 四、入库契约（采集 → DuckDB）

所有平台统一写入 `social_posts` 表（schema 见 `tools/etl/schema_v2.sql`），字段契约：

| 字段 | 说明 | 铁律 |
|---|---|---|
| `post_id` | `{platform}\|{handle}\|{native_id}` 的 sha1 | PRIMARY KEY，幂等 |
| `platform_code` | reddit/tiktok/instagram/youtube/facebook | 不可空 |
| `brand_mentions` | 从 `config/competitor_dictionary.json` 的 `brand_watchlist_flat` 匹配 | 单一词典，无硬编码 |
| `published_at` / `fetched_at` | 发布时间 / 采集时间 | 都必填，区分事实与采集 |
| 缺失指标 | 记 `NULL`，不记 0 | 覆盖率诚实表达 |

**统一入库路径**：

```
采集器（SDK 调用）→ 标准化为 social_posts 行 → INSERT OR IGNORE（幂等去重）
                                  → 同时写 data/processed/social/*.json（原始归档）
```

**竞品词典接入**：所有采集器的品牌匹配改用 `config/competitor_dictionary.json`（批次 2 T3 已产出），删除各采集器内的 `BRAND_WATCHLIST` 硬编码。
