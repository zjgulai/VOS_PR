# PR 核心媒体洞察 P0 Goal 执行契约

## 推荐执行版（中文，可直接复制）

/goal 基于已批准的 Momcozy PR Intelligence Agent PRD Canonical v1.2，按实施计划的 Gate 0 到 Gate 7 顺序，建成 US edition、English、pumping 范围的 PR 核心媒体洞察 P0：导入并可追溯 11 家媒体和 48 位候选编辑，为 11 家媒体建立带权利、允许字段、保留期、连接状态和人工降级的 Source Capability，实现近 30 天增量与最多 180 天基线的 Document、Byline、Content Attribute、Coverage、Evidence、Competitor View、Momcozy Presence、Opportunity、Media Risk、Relationship Constraint、Media Brief 和人工审批 Action；连续两轮为 11 家媒体产出媒体级 Brief 或明确 Coverage Gap，仅对身份和证据达标的编辑产出编辑级 Brief，并以两轮 UAT 证据形成 Go/No-Go 决策。

验证：运行 `python3 -m unittest discover -s tests -p 'test_pr_core_media_*.py' -v`、`python3 -m unittest tests.test_pr_media_api -v`、`python3 -m compileall tools/pr_intel/core_media tools/etl app/dashboard/backend`、离线 source validation、15 个剧本的 fixture UAT、删除定位 dry-run 和 frontend `npm run build`；获准后执行至少一个真实来源的只读 smoke 与两轮业务 UAT，保存 run manifest、Coverage 报告、Brief 包、Action 审计日志、指标快照、命令输出和页面检查证据。

约束：高影响结论可追溯率为 100%，未授权外部动作为 0 次，无依据高优先级 Media Risk 为 0 条；将署名不明确的文档降级到媒体级，将没有观测到、来源失败、限速、结构变化、身份失效和真实零值保持为不同状态；不绕过登录、付费墙、robots、频率限制或访问控制，不自动采集 LinkedIn，不把媒体官方账号当作编辑账号，不实现自动邮件、私信、pitch 或发布。

边界：只修改实施计划列出的 `config/pr_core_media_*`、`tools/pr_intel/core_media`、`tools/etl/migrations/pr_core_media`、`tools/etl/apply_pr_core_media_migrations.py`、`tests/test_pr_core_media_*`、`tests/fixtures/pr_core_media`、`app/dashboard/backend` 的 PR media router/service/main 接入、`app/dashboard/frontend` 的 PR media 页面/组件/API/导航/样式、`PRD/work_log` 的本项目文档和 `.gitignore` 的 PR runtime 排除规则；不覆盖原工作簿、现有 SI/YouTube 代码与配置、无关用户变更、`main` schema 旧表或生产 DuckDB，真实运行数据只写被 Git 排除的 runtime 路径。

迭代策略：按 Gate 0 业务签字、Gate 1 合同与 schema、Gate 2 名录与 capability、Gate 3 采集与 Coverage、Gate 4 文档与洞察、Gate 5 Brief 与 Action、Gate 6 API/UI、Gate 7 两轮 UAT 前进；每个任务先写失败测试，最小实现后运行定向检查，进入下一 Gate 前运行阶段全量测试；失败时先读日志和数据合同，同一问题最多进行 3 轮有新证据的聚焦改进，第 3 轮仍失败则停止局部修补并审查架构或请求人工决策。

完成条件：11 家媒体和 48 位候选编辑的导入与原行可追溯通过，11/11 媒体有明确 edition 或阻塞状态与 Source Capability，至少一个真实获准入口和人工 URL 降级跑通，15 个离线验收剧本全部通过，两轮真实 UAT 产出 11 家媒体的 Brief 或 Coverage Gap 并完成人工评审，硬门槛全部通过，候选指标达到已签字值，所有测试、构建、日志、导出、指标和 Go/No-Go 决策都有新鲜证据，且未完成项如实报告。

暂停条件：需要媒体版权或数据使用判断、付费订阅或供应商合同、凭证或 secret、真实来源批准、生产数据库写入、破坏性迁移或删除、edition 和编辑任职的业务裁决、P0 词典与冷却规则签字、审批人或 Action owner 决定、对外联系或超出 US/en/pumping/11 家媒体的范围扩张时暂停并请求明确授权。

## 默认选择理由

先用合同、合成 fixture、人工 URL 降级和独立 DuckDB schema 证明核心链路，再逐家开启获准来源，能在不伪造覆盖和不破坏现有社媒数据链路的前提下最快得到可评审的 PR 业务价值。

## Goal Draft English-compatible

/goal Build the Momcozy PR Core Media Insight P0 from the approved PR Intelligence Agent PRD Canonical v1.2 by executing Gates 0 through 7 in order. Deliver an auditable US edition, English, pumping scope that imports and traces 11 outlets and 48 candidate journalists; defines rights, allowed fields, retention, access state, and manual fallback for every source; implements 30-day incremental and up-to-180-day baseline collection, Document, Byline, Content Attribute, Coverage, Evidence, Competitor View, Momcozy Presence, Opportunity, Media Risk, Relationship Constraint, Media Brief, and human-approved Action; and completes two UAT rounds that produce an outlet-level Brief or explicit Coverage Gap for all 11 outlets while producing journalist-level Briefs only for identity-verified and evidence-sufficient journalists.

Verification: run the complete PR core media unit suite, PR media API tests, Python compile checks, offline source validation, the 15-scenario fixture UAT, deletion-location dry-run, and the frontend production build; after explicit approval, run one sanitized live read-only source smoke and two business UAT rounds, preserving run manifests, Coverage reports, Brief packages, Action audit logs, metric snapshots, command output, and page inspection evidence.

Constraints: maintain 100 percent traceability for high-impact conclusions, zero unauthorized external actions, and zero unsupported high-priority Media Risk records; downgrade uncertain bylines to outlet level; preserve distinct states for no match, source failure, rate limits, schema changes, invalid profiles, unknown values, and confirmed zero values; do not bypass login, paywall, robots, rate limit, or access controls; do not automate LinkedIn collection or infer personal journalist accounts from outlet accounts; and do not implement automatic email, direct message, pitch, or publishing.

Boundaries: write only to the PR core media configuration, domain package, isolated DuckDB migration, tests and synthetic fixtures, PR media API and UI integration files, project work-log documents, and the PR runtime ignore rule named in the implementation plan; preserve the original workbook, unrelated SI and YouTube code and configuration, unrelated user changes, existing main-schema tables, and the production DuckDB, and keep real runtime data only in ignored runtime paths.

Iteration policy: proceed gate by gate with test-first implementation, run focused checks after each meaningful change and full relevant checks before advancing, inspect logs and contracts before retrying, and make no more than three evidence-producing focused improvement rounds for the same failure before stopping local patches and reviewing architecture or requesting a human decision.

Stop when: the 11-outlet and 48-candidate import is traceable, all 11 outlets have a confirmed edition or explicit block and a Source Capability, one approved live source and manual URL fallback pass the data chain, all 15 offline scenarios pass, two real UAT rounds produce reviewed outlet Briefs or Coverage Gaps, every hard gate passes, signed quality thresholds are met, fresh test and build evidence is saved, and all remaining limitations are explicitly reported.

Pause if: the work requires a copyright or data-use judgment, paid subscription or vendor contract, credential or secret, live-source approval, production database write, destructive migration or deletion, business resolution of edition or journalist affiliation, approval of product dictionaries or cooldown rules, reviewer or Action owner selection, any external contact, or scope expansion beyond US edition, English, pumping, and the 11 approved outlets.
