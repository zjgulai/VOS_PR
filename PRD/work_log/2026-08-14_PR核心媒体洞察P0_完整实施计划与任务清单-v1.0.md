# PR 核心媒体洞察 P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not start a task whose entry gate is not satisfied.

**Goal:** 建立一套可审计、可降级、可删除定位的 PR 核心媒体洞察 P0，在 US/en/pumping 范围内导入 11 家媒体和 48 位候选编辑，连续两轮产出媒体级 Media Brief 或明确 Coverage Gap，并为身份与证据达标的编辑产出编辑级 Brief。

**Architecture:** 采用“名录与权利控制面 → 连接器与原始包络 → Document/Byline/Coverage 标准化 → Signal/Evidence 分析 → Brief/Opportunity/Media Risk → 人工审批 Action”的分层流程。分析仓库沿用 DuckDB，但新表全部置于独立 `pr_core_media` schema，避免与现有 `main.dwd_evidence` 和 `main.ads_action` 字段冲突。采集层使用统一 Connector 协议，每个来源先经 capability/rights 门禁；没有获批的自动来源降级为 `manual_url`，不伪造自动覆盖。

**Tech Stack:** Python 3，标准库 `unittest`，`openpyxl 3.1.5`，`httpx 0.28.1`，`beautifulsoup4 4.14.3`，`feedparser 6.0.12`，`duckdb 1.4.5`，FastAPI/Pydantic 2，Next.js 16/React 19/TypeScript 5.7。实施时先使用项目已有依赖，不引入新的爬虫、队列、数据库或 LLM 框架。

## Global Constraints

- 所有实施路径和命令都相对于项目根目录 `/Users/lute/Project/voc-data-product`；任务开始时先切换到该目录并检查当前 branch 与 `git status --short`。
- 唯一 P0 范围是 US edition、English、pumping/breast pump、11 家核心媒体和 48 位候选编辑；UK、368 家媒体池、多品类和完整 P4 危机预警均不进入本计划。
- 所有媒体、edition、编辑、任职关系和触点必须使用不同 ID；仅凭姓名、媒体名或 URL 不自动合并。
- 编辑身份或任职关系不确定时，`journalist_id=null`，文档只能进入媒体/edition 级分析。
- `no_match`、`source_unavailable`、`rate_limited`、`schema_changed`、`profile_invalid`、`permission_pending` 和 `unknown` 是不同状态；任何一种都不得改写为“该媒体没有报道”。
- 来源未经授权或权利不明时不发起真实请求；不绕过 robots、登录、付费墙、频率限制或访问控制。
- LinkedIn 和其他职业身份页默认 `manual_verification_only`；媒体官方社媒只作 discovery，不归属为编辑个人账号。
- 原始数据只保存权利标签允许的字段；不在 Git 中提交原工作簿、真实采集正文、凭证、私人联系方式或关系备注。
- 高影响结论的证据可追溯率必须为 100%；无相关证据的高优先级 Media Risk 必须为 0 条。
- 所有 Action 默认 `approval_status=pending`。未经人工批准，不得进入 `in_progress`，不得调用邮件、私信、发布或媒体联络接口。
- 所有写库必须显式传入 `--db`；单元与集成测试使用临时 DuckDB，不写 `data/warehouse/voc.duckdb`。
- 错误必须结构化记录，不得使用 `except Exception: pass` 或将失败计为 0 条成功。
- 每个任务先写失败测试，再做最小实现；修改后先运行定向测试，阶段门禁再运行全量相关测试。
- 不自动 commit。只有用户明确授权时，才在每个 Gate 通过后创建小颗粒 commit。

### 2.1 已验证事实

- 工作簿 `吸奶器核心媒体池` 有 11 家媒体和 48 位有姓名的候选编辑。
- 48 位候选编辑中，职位有值 33 条，LinkedIn 有值 14 条，个人简介/作者页有值 25 条，cooperation 有值 38 条，owner 有值 21 条。

- `1-3 高权重SEO GEO Listicle` 有 23 条实际记录，可作为首批人工标注样本，但不构成完整历史语料。
- 现有 `tools/pr_intel/feed_collector.py` 配置了 8/11 家核心媒体；Forbes Personal Shopper、Consumer Reports 和 MomJunction 没有已配置的核心入口。
- 现有 RSS dry-run 不能证明已覆盖 11 家媒体；部分来源返回 0，且通用风险词产生过 P0 误报。
- 现有 `feed_collector.write_to_db` 和 `risk_scorer.write_risk_signals` 存在静默吞异常，不符合新 P0 可观测性要求。
- 现有 `main.ads_action`、`main.dwd_evidence` 与 v1.2 逻辑合同不同，不能在无迁移和兼容设计的情况下直接复用。

### 2.2 工程推断

- 最小风险路径是先交付媒体级 Brief 和人工 URL 降级，再逐家开启获准自动连接器。
- 使用 DuckDB 独立 schema 可以保留现有数据仓库，又避免实体和 Action 表的同名冲突。
- 工作簿不宜直接写入正式名录；必须先生成 preview，再通过显式 approve 生成不可变导入版本。

### 2.3 会阻塞真实采集、UAT 或上线声明的不确定项

1. 11 家媒体的 US edition 域名、作者页、RSS、授权媒体库入口和可保存字段。
2. 48 位候选编辑的当前任职、作者页、edition 归属和 UAT 优先级。
3. P0 吸奶器 SKU、BP 别名、拼写变体和竞品词典的业务签字版本。
4. 媒体库/记者数据库订阅、全文、导出、历史、保留和删除权利。
5. relationship event、同题冷却、禁联、关系风险和人工解除的 RACI。
6. Brief 人工 baseline、质量阈值、评审人、Action owner 和 Go/No-Go 签字人。

### 3.3 Source Capability 必填字段

`config/pr_core_media_source_capabilities.json` 每一条记录必须含有：

```json
{
  "version": "1.0",
  "source_id": "source_babylist_rss_us_en",
  "edition_id": "edition_babylist_us_en",
  "source_type": "commerce_editorial",
  "collection_method": "rss",
  "entrypoint": "https://www.babylist.com/hello-baby/feed",
  "permission_status": "pending",
  "permission_evidence_ref": "decision://gate0/source-rights/babylist",
  "rights_label": "metadata_only",
  "allowed_fields": ["title", "canonical_url", "author_text", "published_at", "excerpt"],
  "retention_days": 90,
  "collection_frequency": "daily",
  "historical_window_days": 180,
  "credential_ref": null,
  "access_status": "untested",
  "last_tested_at": null,
  "last_success_at": null,
  "fallback_method": "manual_url",
  "fallback_source_id": "source_babylist_manual_us_en",
  "owner_role": "data_engineer",
  "reviewer_role": "pr_analyst"
}
```

校验规则：

- `permission_status` 只能为 `approved/pending/blocked/manual_only`。
- `access_status` 只能为 `available/unavailable/rate_limited/schema_changed/untested/profile_invalid`。
- `rights_label` 只能为 `full_text_allowed/excerpt_only/metadata_only`。
- `permission_status != approved` 时，自动 connector 不得发起真实请求。
- `credential_ref` 只保存运行时 secret 名称或密钥管理器引用，不得保存值。
- `historical_window_days` P0 不得大于 180，日常增量窗口为 30 天。
- `fallback_method` 在 P0 必须是 `manual_url` 或明确 `none_with_reason`。

### 3.4 Connector 统一输入输出

```python
@dataclass(frozen=True)
class CollectionRequest:
    run_id: str
    source_id: str
    edition_id: str
    window_start: datetime
    window_end: datetime
    cursor: str | None
    dry_run: bool

@dataclass(frozen=True)
class RawEnvelope:
    raw_object_ref: str
    payload_sha256: str
    source_id: str
    fetched_at: datetime
    rights_label: str
    records: tuple[dict[str, object], ...]

@dataclass(frozen=True)
class CollectionResult:
    run_id: str
    source_id: str
    status: str
    items_seen: int
    items_accepted: int
    next_cursor: str | None
    raw_envelopes: tuple[RawEnvelope, ...]
    error_code: str | None
    error_message: str | None
```

Connector 只能返回以下互斥状态：`success`、`no_match`、`source_unavailable`、`rate_limited`、`schema_changed`、`profile_invalid`、`permission_pending`、`blocked`、`partial`。`items_accepted=0` 时仍必须有状态、实际窗口和错误代码。

### 3.5 原始包络和保留

P0 本地试点的运行时路径是：

```text
data/processed/pr_core_media/
+-- raw/{source_id}/{yyyy}/{mm}/{dd}/{run_id}/{sha256}.json
+-- manifests/{run_id}.json
+-- imports/{import_version}/preview.json
+-- imports/{import_version}/approved.json
+-- uat/{uat_round}/
+-- deletion_audits/{request_id}.json
```

- `data/processed/` 已被 `.gitignore` 排除；真实数据不复制到 `tests/fixtures/`。
- `metadata_only` 包络只保存获准元数据和指纹，不保存全文。
- `excerpt_only` 只保存签字允许的最小片段长度，生成 Evidence 时不扩大片段。
- 超过 `retention_days` 的原始包络先做定位 dry-run，再由授权角色执行删除；派生结论需重新生成或标记失效。

### 3.6 标准化和 Coverage 判定顺序

```text
Scope 已签字
  → Source Capability 通过权利门禁
  → Connector 返回 CollectionResult
  → RawArchive 按 rights_label 写入或只记引用
  → canonical URL / edition / timestamp / content type 标准化
  → byline 候选解析
  → affiliation 核验门禁
  → document 去重与转载聚类
  → Coverage 按来源和时间窗口汇总
  → 只有可引用 Document 进入 Signal/Evidence
```

Coverage 状态的优先级是：权利/访问失败高于零匹配，部分覆盖高于完整。只有连接成功、完整读取定义窗口且经过范围过滤后为零，才能使用 `no_match`。

## 4. 物理数据模型与文件边界

### 4.1 DuckDB schema

所有新表使用 `pr_core_media.<table>` 全限定名。

| 层 | 表 | 一行粒度 | 核心约束 |
|---|---|---|---|
| Control | `schema_migrations` | 一个迁移版本 | migration_id 和 checksum 唯一 |
| Control | `ctl_import_batch` | 一次工作簿预览/批准 | preview 与 approved 分离，批准后不可改 |
| Control | `ctl_import_record` | 一个 sheet 原始行 | `source_file_ref/source_sheet/source_row_ref/raw_hash` 必填 |
| Control | `ctl_source_capability` | 一个 source+edition+method | 权利、可存字段、保留期和 fallback 必填 |
| Control | `ctl_collection_job` | 一次 source 窗口执行 | 状态、起止时间、cursor、数量和错误不可混写 |
| DIM | `dim_outlet` | 一个媒体品牌 | 不存 edition/编辑字段 |
| DIM | `dim_outlet_edition` | 一个国家/语言/域名版本 | P0 确定结论仅允许 verified US/en |
| DIM | `dim_journalist` | 一个公开职业身份 | 同名不自动合并 |
| Bridge | `bridge_journalist_affiliation` | 一段任职关系 | verified+active 才允许编辑级归属 |
| DIM | `dim_touchpoint` | 一个公开触点 | entity/ownership/collection policy 一致 |
| ODS | `ods_raw_envelope` | 一个原始包络引用 | 记录 sha256、rights、retention 和 object ref |
| DWD | `dwd_document` | 一篇文档 | source+text_hash 唯一，edition 必填，journalist 可空 |
| Bridge | `bridge_document_byline` | 一个文档的一个署名候选 | 支持多人署名和冲突候选 |
| DWD | `dwd_editorial_signal` | 一条主题/竞品/出现/风险信号 | 证据片段、内容属性、模型/规则版本必填 |
| DWD | `dwd_claim` | 一条可证伪主张 | fact/inference 分开，有 review status |
| DWD | `dwd_evidence` | 一条 claim-document 证据 | supports/refutes 和 grade 必填 |
| Bridge | `bridge_evidence_set_item` | 一个证据集成员 | evidence_set_id+evidence_id 唯一 |
| DWD | `dwd_relationship_event` | 一条关系事件 | 无 occurred_at 只能当备注 |
| DWD | `dwd_pitch_constraint` | 一条 pitch 约束 | reason/start/end/status/evidence/approver 可审计 |
| DWS | `dws_source_coverage` | source+edition+周期 | 实际覆盖、状态、最后成功和恢复动作 |
| DWS | `dws_edition_period` | edition+周期 | topic/stance/sample/coverage |
| DWS | `dws_journalist_period` | journalist+周期 | 只汇总 verified affiliation 文档 |
| ADS | `ads_media_brief` | 一份版本化 Brief | scope/window/coverage/evidence/review/version 必填 |
| ADS | `ads_opportunity` | 一个机会 | angle/why now/asset gap/risk penalty/evidence |
| ADS | `ads_media_risk` | 一个核心媒体风险候选 | brand/product relevance 门禁和人工 review |
| ADS | `ads_action` | 一个 PR Action | approval 与 execution 分开，无外部发送字段 |
| ADS | `ads_feedback` | 一条人工标注/驳回/采纳 | reviewer role、reason、created_at 必填 |

### 4.2 稳定 ID 规则

- `outlet_id = "outlet_" + sha256(normalized_canonical_name)[:16]`
- `edition_id = "edition_" + sha256(outlet_id + "|" + country + "|" + language + "|" + canonical_domain_or_unknown)[:16]`
- `journalist_id = "journalist_" + sha256(import_version + "|" + source_sheet + "|" + source_row_ref + "|" + normalized_public_name)[:16]`
- `document_id = "document_" + sha256(source_id + "|" + canonical_url + "|" + published_at_iso)[:20]`
- `text_hash = sha256(normalized_permitted_text)`
- `brief_id = "brief_" + sha256(scope_type + "|" + scope_id + "|" + window_start + "|" + window_end + "|" + rule_version + "|" + model_version)[:20]`

ID 生成函数必须是纯函数，同一 fixture 重跑结果一致。编辑 ID 不使用姓名全局去重，避免同名误合并。

### 5.2 顶级风险与预案

| 风险 | 触发信号 | 预案 | owner role |
|---|---|---|---|
| 来源权利不明 | capability 无权利证据或可存字段 | 自动 connector 保持 `pending`，使用获准 `manual_url` 或 Coverage Gap | Legal + Data Lead |

| 全文不允许保存 | rights 仅允许 excerpt/metadata | 只保存允许片段/元数据和指纹，Brief 明示证据限制 | Legal + Data Lead |
| 署名 precision 不达标 | 同名、多人署名、转岗误归属 | 提高 verified affiliation 门槛，扩大降级而不扩大猜测 | PR Analyst + Data Lead |

## 8. 数据质量、日志和运维要求

### 8.1 每次 run 的必填指标

- 范围：scope_id、scope_version、edition 数、journalist 候选数。
- 采集：source_id、requested/actual window、items_seen/accepted/rejected、cursor、HTTP 状态分布。
- 质量：无效时间、无效 URL、重复、edition 冲突、署名冲突、内容属性 unknown 比率。
- 分析：signal 按类型计数、风险相关性驳回数、evidence 缺失数、模型/规则版本。
- 产出：Brief 按 media/journalist 计数、Coverage Gap 数、Opportunity/Media Risk/No-pitch/Action 数。
- 审批：pending/approved/rejected/blocked/expired 数，未授权外部动作数。
- 性能：每阶段 duration_ms、最慢 source、证据查询 P50/P95、批次生成时间。

### 8.2 日志红线

- 不记录 API key、cookie、Authorization header、私人联系方式、完整正文或工作簿中的关系备注。
- 错误日志保留 request_id、run_id、source_id、stage、error_code、safe_message 和 recovery_action。
- 工作簿预览默认只输出计数和 source_row_ref，不在终端打印全部编辑数据。
